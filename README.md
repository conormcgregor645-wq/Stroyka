# Метраж — строительные калькуляторы

Сайт: **https://metrazh.online/**

Статический сайт с одиннадцатью калькуляторами ремонта. Работает без сервера и сборщика: подходит для GitHub Pages, Netlify или любого хостинга.

| Страница | Что считает |
|---|---|
| `plitka.html` | плитка для пола и стен, упаковки, клей, затирка, крестики |
| `oboi.html` | рулоны с учётом раппорта и подгонки, клей, обрезки |
| `kraska.html` | литры и банки краски, грунтовка, малярный скотч |
| `laminat.html` | упаковки ламината, подложка, плинтус, порожки |
| `shtukaturka.html` | мешки гипсовой или цементной штукатурки, маяки, грунтовка |
| `shpaklevka.html` | стартовая и финишная шпаклёвка, грунтовка, абразив |
| `gipsokarton.html` | листы ГКЛ, профиль, подвесы, саморезы, дюбели, серпянка |
| `uteplitel.html` | плиты и упаковки утеплителя, объём, пароизоляция, дюбели |
| `styazhka.html` | сухая смесь или цемент с песком, фибра, демпферная лента |
| `nalivnoy-pol.html` | наливной пол: смесь в кг и мешках по средней толщине слоя, грунтовка, демпферная лента, разрез пола |
| `kirpich.html` | кирпич, раствор, цемент и песок для кладки |

Оформление: фон-миллиметровка, шрифты Manrope и JetBrains Mono (свои файлы в `assets/fonts`, без Google Fonts), тёмная карточка результата, схема комнаты в масштабе (SVG, для плитки и ламината — с раскладкой), на телефоне — прилипающая полоса с итогом внизу экрана. Цвета задаются переменными в начале `assets/style.css`.

На каждой странице калькулятора: хлебные крошки, блок «Как считается», таблица норм расхода, частые вопросы, разметка Schema.org (BreadcrumbList, FAQPage, WebApplication). Размеры комнаты запоминаются и подставляются в другие калькуляторы. Расчётом можно поделиться ссылкой или распечатать его.

## Главная

Первый экран — текст «Сколько плитки, обоев и смеси нужно на ваш ремонт?» с кнопками «Посчитать весь ремонт» (`remont.html`) и «Выбрать материал ↓» (`#calc`), справа — объёмная ванная `assets/hero-3d-vannaya.svg` (встраивается в страницу инлайном при сборке) и две карточки с расчётом плитки для ванной 2×2 м. Цифры карточек `tools/build.py` считает теми же формулами, что статья про ванную, и останавливает сборку, если они разойдутся. До 900 px колонки идут друг под другом. В тёмной теме иллюстрация остаётся светлой, оранжевое пятно за ней приглушено. Ниже — «Ремонт под ключ» и «Калькуляторы материалов».

## Ремонт под ключ

Хабы считают материалы на весь ремонт помещения по этапам — по одним размерам комнаты (общая память размеров с калькуляторами) и шаблонам комнат.

| Страница | Этапы |
|---|---|
| `remont-vannoy.html` | выравнивание стен (штукатурка), стяжка пола, плитка на стены и пол, клей и затирка, покраска потолка |
| `remont-kuhni.html` | штукатурка и шпаклёвка стен, плитка на фартук (2,5 × 0,6 м по умолчанию), покраска или обои, ламинат или плитка на пол |
| `remont-komnaty.html` | утепление наружной стены (переключатель), шпаклёвка, обои или покраска, ламинат, плинтус |
| `remont.html` | список хабов — пункт меню «Ремонт под ключ» |

- Каждый этап считает `assets/calc.js` теми же формулами, что отдельный калькулятор, и с его значениями по умолчанию: `tools/build.py` собирает их из форм калькуляторов (`CALC_DEFAULTS`) и кладёт в страницу хаба (`<script id="hub-data">`). Логика этапов — `assets/hub.js`, сами этапы — функции `hub_bath`, `hub_kitchen`, `hub_room` в `tools/build.py`.
- Ссылка «Уточнить в калькуляторе» открывает калькулятор с теми же значениями — результат совпадает с этапом. Ссылки на фартук и наружную стену несут `mem=0`, чтобы калькулятор не записал их в общую память размеров комнаты.
- «Добавить всё в список покупок» — материалы всех видимых этапов, кнопка у этапа — только его материалы. Блок «Купить» с партнёрскими ссылками и маркировкой, частые вопросы, Schema.org (BreadcrumbList, FAQPage).
- Этап «Наливной пол» в хабе ванной появляется автоматически, когда в сборке есть калькулятор наливного пола (сейчас — только в ветке `calc/nalivnoy-pol`).
- Ссылки «Весь ремонт ванной →» стоят на калькуляторах плитки и стяжки (`HUB_LINKS` в `tools/build.py`), карточки хабов — на главной над калькуляторами.

## Сервисные страницы и функции

- **`privacy.html`** — политика конфиденциальности (шаблон: сверьте с юристом), **`o-sajte.html`** — о сайте. Ссылки в подвале, обе страницы в sitemap. Контакт — константа `CONTACT_EMAIL` в `tools/build.py` (сейчас franceone1@mail.ru).
- **Уведомление о cookie** внизу экрана показывается один раз (отметка в localStorage) и поднимается над полосой итога на телефоне — `assets/site.js`.
- **Шаблоны комнат** над полями «Помещение»: «Ванная 2×2», «Санузел 1,5×1,5», «Кухня 3×3», «Комната 3×4», «Комната 4×5» — размеры и проёмы задаются в `PRESETS` в `tools/build.py`.
- **Список покупок**: кнопка «Добавить в список покупок» под результатом, значок с числом позиций в шапке, страница **`spisok.html`** (noindex, не в sitemap) — удаление, очистка, печать, «Поделиться ссылкой» (список кодируется в адрес). Хранится в localStorage; логика страницы — `assets/list.js`.
- **Светлая и тёмная тема — по местному времени посетителя**: с 08:00 до 17:59 светлая, с 18:00 до 07:59 тёмная (время устройства, `new Date().getHours()`). Часы смены — константы `THEME_DAY_START = 8` и `THEME_NIGHT_START = 18` в `tools/build.py`: поменяйте и пересоберите сайт.
  - Скрипт в `<head>` (`THEME_INIT`) ставит `data-theme` на `<html>` до отрисовки, чтобы страница не мигала, и меняет `meta theme-color` (цвет панели браузера на телефоне: светлая `#F5F1EA`, тёмная `#0D0F11`, константа `THEME_COLORS`).
  - Кнопки переключения нет. Ручной выбор из прошлой версии (localStorage `rk-theme` со сроком `until`) учитывается до своего срока и удаляется, значения без срока удаляются сразу.
  - Если вкладка открыта во время смены, тема меняется сама: проверка раз в минуту и при возвращении на вкладку (`assets/site.js`).
  - Без localStorage работает одно расписание; без JavaScript тема — по настройке системы (`prefers-color-scheme`). Цвета — переменные в начале `assets/style.css`; печать всегда в светлой теме.
- **Домашний экран**: `site.webmanifest` и иконки `assets/icon-192.png`, `assets/icon-512.png`. Service worker нет.
- **«Расчёт пригодился?»** под карточкой результата во всех калькуляторах и хабах: «Да» / «Нет», при «Нет» — необязательное поле «Что было не так?» (до 200 символов). Ответ уходит только целью Метрики `feedback_yes` / `feedback_no` (параметры `calc` и `text`), после ответа блок на этой странице больше не показывается (localStorage `rk-feedback`).
- **Шрифты** Manrope (400, 600, 700, 800) и JetBrains Mono (500, 700) — woff2, поднаборы cyrillic и latin, `assets/fonts/` (лицензия OFL 1.1 там же). `@font-face` с `font-display: swap` — в начале `assets/style.css`, в `<head>` предзагрузка Manrope 400 и 800 (кириллица). Всего ≈ 142 КБ, браузер грузит только нужные поднаборы.
- **Живой итог**: главное число в карточке результата плавно меняется за 200 мс; при `prefers-reduced-motion` — без анимации.

## IndexNow (Яндекс)

Ключ IndexNow — файл `816d5fecf3332da97c4a9308a42abc46.txt` в корне сайта (имя файла = ключ, внутри — тот же ключ).

- Workflow `.github/workflows/indexnow.yml` запускается после каждого пуша в `main`, который меняет HTML-страницы. Скрипт `tools/indexnow.sh` берёт изменённые страницы, оставляет те, что есть в `sitemap.xml` (служебные noindex-страницы не отправляются), ждёт публикации коммита на GitHub Pages и отправляет POST на `https://yandex.com/indexnow` с полями `host`, `key`, `keyLocation`, `urlList`.
- Ошибка запроса не роняет workflow: в журнале остаётся предупреждение.
- Пуши из самого GitHub Actions не запускают другие workflow, поэтому публикация наливного пола (`publish-calc-nalivnoy-pol.yml`) вызывает тот же скрипт последним шагом.
- Отправить вручную: `bash tools/indexnow.sh <коммит-до> <коммит-после>`.
- Сменить ключ: удалите старый файл, создайте новый `<32 hex-символа>.txt` с ключом внутри — скрипт найдёт его сам.

## Превью для соцсетей и схемы

- У каждой страницы своё превью 1200×630 — `assets/og/<страница>.png` (графитовый фон, миллиметровка, логотип, название страницы). В `<head>` прописаны `og:image`, `og:image:width`, `og:image:height`, `og:image:alt` и `twitter:card=summary_large_image`. Страница 404 использует превью главной.
- Картинки рисует `tools/og/render.cjs` по списку `tools/og/pages.json`, который пишет `tools/build.py`. После добавления страницы или смены заголовка:

  ```bash
  python3 tools/build.py
  cd tools/og && npm install && node render.cjs          # все страницы
  node render.cjs plitka oboi                            # или только нужные
  ```

- Схемы на страницах (как измерить ванную, раскладка плитки, раппорт, смещение рядов ламината, разрез стяжки) — инлайн-SVG из `tools/schemes.py`. Цвета берутся из CSS-переменных, на телефоне схема по ширине экрана, отрисовка отложена до прокрутки (`content-visibility: auto`).

Шапка, меню, подвал, тексты и SEO-разметка всех страниц описаны в `tools/build.py`. После правок в нём пересоберите сайт:

```bash
python3 tools/build.py
```

Нужен только Python 3. Правки, внесённые вручную прямо в HTML, при пересборке затираются, поэтому меняйте тексты в `tools/build.py`.

### Яндекс Метрика

Счётчик **113822395** подключается из `assets/site.js` на всех страницах. Чтобы сменить его, поменяйте номер в `assets/site.js` и `tools/build.py` и пересоберите страницы.

Сайт отправляет цели (`reachGoal`). Создайте их в Метрике: «Цели → Добавить цель → JavaScript-событие».

| Идентификатор цели | Когда срабатывает | Параметры |
|---|---|---|
| `calc_done` | первый расчёт после ввода данных пользователем (один раз за визит) | `calc` — калькулятор |
| `affiliate_click` | клик по кнопке «Купить в Максидоме» или маленькой кнопке под ней | `calc` — калькулятор, `item` — ключ ссылки (например `PLITKA`, `ZATIRKA`), `shop` — `maxidom` |
| `preset_click` | нажатие на шаблон комнаты («Ванная 2×2», «Комната 3×4»…) | `calc`, `preset` — название шаблона |
| `list_add` | «Добавить в список покупок» под результатом; в хабах — «Добавить всё» или кнопка этапа | `calc`; в хабах ещё `stage` — id этапа или `all` |
| `feedback_yes` | «Да» на вопрос «Расчёт пригодился?» | `calc` |
| `feedback_no` | «Нет» и «Отправить» | `calc`, `text` — что было не так (до 200 символов, может быть пустым) |

В хабах `calc` — `hub-bath`, `hub-kitchen` или `hub-room`.

### Реклама РСЯ

Место под блок находится между калькулятором и текстом статьи (`<div class="ad-slot" data-rsy>`). На телефоне оно идёт после результата и не перекрывает его. Пока `RSY_BLOCK_ID` не задан, блок скрыт и места не занимает. После замены `assets/site.js` сам подгружает `context.js` Яндекса и выводит блок.

## Домен и название сайта

Сайт работает на домене **metrazh.online**. Адрес и название заданы в начале `tools/build.py`:

```python
SITE_URL = "https://metrazh.online/"   # базовый адрес со слешем на конце
SITE_NAME = "Метраж"                   # шапка, подвал, og:site_name, страница 404
```

После изменения запустите `python3 tools/build.py`. Обновятся `canonical`, `og:url`, разметка Schema.org, `sitemap.xml`, `robots.txt` и файл `CNAME`. Для адреса на `*.github.io` файл `CNAME` удаляется.

### Подключение metrazh.online к GitHub Pages

1. В DNS у регистратора домена создайте записи для `metrazh.online`:

   | Тип | Имя | Значение |
   |---|---|---|
   | A | `@` | `185.199.108.153` |
   | A | `@` | `185.199.109.153` |
   | A | `@` | `185.199.110.153` |
   | A | `@` | `185.199.111.153` |
   | CNAME | `www` | `conormcgregor645-wq.github.io` |

   Для IPv6 можно добавить AAAA-записи `2606:50c0:8000::153`, `2606:50c0:8001::153`, `2606:50c0:8002::153`, `2606:50c0:8003::153`.
2. В репозитории: Settings → Pages → Custom domain. Там должно стоять `metrazh.online` (GitHub подхватывает его из файла `CNAME`). Нажмите Save.
3. Когда GitHub проверит DNS (от нескольких минут до суток), включите **Enforce HTTPS**.

Settings → Pages → Deploy from a branch → `main`, папка `/ (root)`. Затем добавьте https://metrazh.online/ в Яндекс Вебмастер и Google Search Console и отправьте `https://metrazh.online/sitemap.xml`.
